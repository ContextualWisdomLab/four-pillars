# Four Pillars v0.8.0 — Release Assurance Doctoring

## Claim boundary

This record supports the software-release claim that Four Pillars v0.8.0 packages the reviewed hourly NVIDIA NIM OpenCode control plane while preserving the deterministic calculation, schema, storage, report, browser-history, and standalone/modular MSA contracts. It does not claim scientific validation of 사주 interpretation, certification to an ISO standard, or that autonomous code generation removes the need for independent review.

## Buyer-visible release gap

Before v0.8.0, commercial maintainers had a deterministic hourly quality sentinel but no isolated product-development control plane that could propose a bounded improvement when the pull-request queue was empty. The release adds a minute-47 loop whose model, verifier, and publisher operate on separate fresh runners. The model can create a proposal but cannot approve, merge, tag, release, or deploy it.

## Exact release controls

- The package, runtime, FastAPI metadata, test contract, changelog section, tag, and release assets use one semantic version: `0.8.0`.
- Direct model execution receives only `NVIDIA_NIM_API_KEY`; `COPILOT_GITHUB_TOKEN` is prohibited and existing reviewer-agent credentials are unchanged.
- The handoff binds base commit, numeric artifact identifier, artifact digest, patch SHA-256, changed-file count, byte count, and Git modes before proposed code is executed.
- Proposed changes pass dependency integrity, repository gap audit, Ruff and public-docstring checks, compilation, documentation and prompt contracts, realistic deterministic fixtures, package build, container build, security scanning, and exactly 100% production statement and branch coverage.
- A release is created only from the reviewed merge commit and includes source distribution, wheel, and `SHA256SUMS` assets. Existing tags and releases are never overwritten.

## Modular and operational boundary

The deterministic calendar engine remains independently usable. Persistence, interpretation, artifact publication, history, and idempotency retain explicit ports for standalone or MSA composition. The hourly development workflow is repository governance rather than a runtime dependency, so central `.github`, `naruon`, and other organization services can adopt or replace it without importing application internals.

## Evidence limitations

GitHub Checks establish that the tested source satisfied the encoded contracts on the recorded commit. They do not prove absence of every defect. Artifact digests establish identity, not semantic correctness. LLM evaluation remains supplementary to deterministic fixtures, schemas, rule-based quality gates, security review, and accountable human governance.
