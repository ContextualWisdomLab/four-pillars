# Four Pillars v0.7.0 Release Implementation Plan

**Goal:** Publish the optional Contextual Orchestrator backend, secure credential-endpoint validation, provider-neutral generation boundary, and APA 7th governance traceability as Four Pillars v0.7.0.

**Architecture:** Preserve deterministic calculation evidence, the direct NVIDIA NIM standalone default, structural MSA ports, strict Pydantic report schemas, durable jobs, privacy-safe artifacts, and the existing v0.6 browser history. Release only the additive organization-backend and governance changes already merged to `main`.

**Tech stack:** Python 3.11/3.12, FastAPI, Pydantic 2, HTTPX, NVIDIA NIM, Contextual Orchestrator, SQLite, ReportLab, Hatchling, pytest, Ruff, Docker, and GitHub Actions.

## Constraints

- Package, Python runtime, and FastAPI versions advance together to `0.7.0`.
- `NVIDIA_NIM_API_KEY` remains exclusive to direct hosted NIM.
- `CONTEXTUAL_ORCHESTRATOR_TOKEN` remains exclusive to the optional organization gateway.
- Contextual Orchestrator uses explicit `auto`, `route`, or `conduct` execution and must not be collapsed into provider passthrough by `response_format`.
- Remote credential-bearing endpoints require HTTPS; loopback HTTP remains a local-development exception.
- No selected-backend failure causes silent provider fallback.
- Public production APIs retain complete docstrings.
- Statement and branch coverage remain exactly 100 percent on Python 3.11 and 3.12.
- Database identifiers remain multi-word supported case; this release changes no database object.
- Release notes follow Keep a Changelog and Semantic Versioning.
- The release does not retag or overwrite v0.6.0.
