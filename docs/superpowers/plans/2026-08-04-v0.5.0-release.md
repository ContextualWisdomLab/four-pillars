# Four Pillars v0.5.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the backward-compatible privacy-safe report-history capability as Four Pillars v0.5.0 with aligned package, runtime, API, changelog, distribution, and GitHub Release surfaces.

**Architecture:** Preserve deterministic calculation, NVIDIA NIM interpretation, all required ports, and the v0.4 idempotency contract. Treat `ReportJobHistoryRepository` and authenticated `GET /v1/reports` as an additive minor release, move their curated Unreleased notes into a dated v0.5.0 section, and use the existing least-privilege release workflow to validate and publish versioned artifacts from `main`.

**Tech Stack:** Python 3.11/3.12, FastAPI, Pydantic 2, SQLite, Hatchling, pytest, coverage.py, Ruff, Docker, GitHub Actions, GitHub CLI release publication.

## Global Constraints

- `NVIDIA_NIM_API_KEY` remains the only hosted NVIDIA NIM credential.
- Statement and branch coverage remain exactly 100%.
- Every production public API retains a complete docstring.
- Database object names contain at least two words and use `snake_case` unless an external system requires camelCase or PascalCase.
- Existing required repository adapters remain compatible; history stays an optional capability.
- Release notes follow Keep a Changelog and Semantic Versioning.
- Release validation never receives the hosted NIM credential.
