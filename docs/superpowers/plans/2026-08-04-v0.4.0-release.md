# Four Pillars v0.4.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the backward-compatible idempotent report-enqueue capability as Four Pillars v0.4.0 with aligned package, runtime, API, changelog, build, and GitHub Release surfaces.

**Architecture:** Keep deterministic calculation, NVIDIA NIM interpretation, and all existing required MSA ports unchanged. Treat `IdempotentReportJobRepository` and the optional HTTP `Idempotency-Key` contract as an additive minor release, move the curated Unreleased notes into a dated v0.4.0 section, and rely on the existing least-privilege release workflow to validate and publish versioned artifacts from `main`.

**Tech Stack:** Python 3.11/3.12, FastAPI, Pydantic, Hatchling, pytest, coverage.py, Ruff, GitHub Actions, GitHub CLI release publication.

## Global Constraints

- `NVIDIA_NIM_API_KEY` remains the only hosted NVIDIA NIM credential.
- Statement and branch coverage must remain exactly 100%.
- Every production public API retains complete docstrings.
- Database object names remain two-or-more-word `snake_case` unless an external system requires camelCase or PascalCase.
- Release notes use Keep a Changelog structure and Semantic Versioning.
- Existing `ReportJobRepository` adapters remain compatible; idempotency stays an optional capability.
- Release validation never receives the hosted NIM credential.
