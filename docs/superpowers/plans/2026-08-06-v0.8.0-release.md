# Four Pillars v0.8.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the secure hourly NVIDIA NIM OpenCode product-development control plane as Four Pillars v0.8.0 without changing deterministic calculation or report contracts.

**Architecture:** Advance package, runtime, and FastAPI versions together after the proposal-only minute-47 workflow has merged to `main`. Move only the implemented Unreleased hourly-agent entries into a dated v0.8.0 section, preserve future product work under Unreleased, and rely on the existing least-privilege release workflow for immutable source, wheel, and checksum publication.

**Tech Stack:** Python 3.11/3.12, FastAPI, Pydantic 2, Hatchling, pytest, Ruff, Docker, GitHub Actions, OpenCode, NVIDIA NIM, GitHub App authentication.

## Global Constraints

- Package, Python runtime, and FastAPI public versions advance together to `0.8.0`.
- Deterministic calculation, prompt, report-schema, database, cursor, idempotency, history, and artifact contracts remain unchanged.
- Direct hosted model work continues to use only `NVIDIA_NIM_API_KEY`.
- `COPILOT_GITHUB_TOKEN` remains prohibited for model execution.
- Existing review-agent identities, variables, secret names, and provider routes remain unchanged.
- The minute-47 workflow may propose one pull request but never approves, merges, tags, releases, or deploys.
- Public production APIs retain complete beginner-readable docstrings.
- Production statement and branch coverage remain exactly 100 percent on Python 3.11 and 3.12.
- Database object naming remains descriptive multi-word `snake_case`; this release changes no database object.
- Release notes follow Keep a Changelog and Semantic Versioning.
- The release does not retag or overwrite v0.7.0.
